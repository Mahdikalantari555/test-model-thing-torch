# Proposal

## Why

The `Experiment` branch contains multiple partial sequence, decision, and plastic-memory primitives (`src/model/rtu.py`, `src/model/decision_head.py`, `src/model/delta_memory.py`, `src/model/knowledge_store.py`, `src/model/confidence.py`), while the lightweight non-Transformer research report proposes three composite architectures (Candidates A, B, and C) plus compact recurrent, attention-only (Needle SAN), and Transformer baselines—none of which have been evaluated in an isolated, parameter-matched, multi-seed comparison. Before locking the built-in offline core of the `recamem` project (`recamem-plastic-memory-engine`), we need a controlled, CPU-feasible experimental harness on the `Experiment` codebase that tests every candidate component separately, proves empirically which combination wins without destructive interference or unverified complexity, and writes out the definitive core specification and evidence ledger for `recamem`.

## What Changes

- **Orthogonal candidate modularity on `Experiment` (`src/model/`):** Factor the report's composite candidates and existing repository modules into five independently swappable slots so no comparison confounds backbone math, tokenization, auxiliary objectives, decision heads, routing, and external memory:
  - **Track 1 — Sequence-Mixing Cores (7 arms):** `C0` existing unstacked diagonal Byte-RTU (`src/model/rtu.py`), `C1` Candidate B stacked input-gated diagonal RTU, `C2` Mamba-style selective diagonal SSM, `C3` RetNet-style pure-decay matrix recurrence, `C4` Candidate A gated-delta matrix core with WY chunkwise scan (`Conv4` ablated on/off) and SwiGLU, `C5` Needle-style sliding-window QK-norm attention-only SAN with pinned sink tokens, and `C6` parameter-matched standard RoPE + QK-norm + SwiGLU Softmax Transformer.
  - **Track 2 — Objectives, Gradient Rules & Tokenizers (5 arms):** `O1` pure cross-entropy with `EOS` token (`--ce-only`, MSE stop head removed), `O2` existing 4-term byte loss (`CE + variance hinge + next-embed MSE + stop MSE`), `O3` Candidate B EMA-teacher chunk-latent cosine prediction + VICReg variance/covariance regularizer, `O4` online per-token exact RTRL eligibility traces vs. micro-batched chunked BPTT with gradient accumulation, and `Tok` raw UTF-8 bytes (`V=256`) vs. compact BPE (`V=4096` with `EOS`, `OPT`, `SEP`, `ROUTE_*`).
  - **Track 3 — System-1 Decision & Calibration Heads (4 arms):** `D1` existing hyperspherical cosine prototype head (`src/model/decision_head.py`), `D2` existing closed-form Ridge regression probe, `D3` Candidate A shared-core option-conditioned bilinear scoring head with dynamic option sets ($K \in [2, 255]$), learned null vector $v_0$, and held-out temperature calibration $T_{\text{cal}}$, and `D4` equal-budget Split-Specialist control (separate LM + dedicated classifier/anchor).
  - **Track 4 — Five-Way Action Routers (4 arms):** Routing across `{generate, classify, retrieve, tool, abstain}` via `R1` deterministic keyword/cosine gate, `R2` thresholded max-probability/energy + `confidence.py` harmonic fusion, `R3` autoregressive `ROUTE_*` tokens + constrained schema decoding, and `R4` Candidate A learned `MLP([u; m])` over pooled + trailing-16 states with deterministic risk-coverage and permission guards.
  - **Track 5 — Lifelong Memory & Adaptation Modules (6 arms):** `M0` persistent session fast-weight state $S_t$, `M1` Candidate C Engram hashed n-gram table (`H=8192 × d` at layers `2` and `L/2`), `M2` Candidate C NLL-surprise-gated top-$k=4$ residual episodic KV store, `M3` existing `KnowledgeStore` + `hybrid_retrieval` RRF (prompt-stuffing vs. gated residual injection), `M4` existing `DeltaPlasticAdapter` & `SparseDeltaAdapter` (TopK-128 sparse coding + Householder erase), and `M5` online weight plasticity (SGD/EWC/RTRL) vs. frozen-weight adaptation.
- **Ceteris-paribus benchmark & 4-stage selection tournament (`scripts/run_core_tournament.py`):** Implement parameter-matched scaling tiers (`Micro ~2M`, `Small ~6M`, `Target ~17M`, within `±2%` budget), per-arm 3-point learning-rate micro-sweeps, RAM-safe micro-batched gradient accumulation (`< 3.8 GiB` CPU environments), cross-tokenizer Bits-Per-Byte (`BPB`) normalization, separate calibration (`val_cal`) and evaluation (`test_eval`) held-out splits, dual Equal-Byte and Equal-Wall-Clock tables, 3-seed/5-seed paired bootstrap 95% confidence intervals, and deterministic offline fixtures whenever external corpora are unreachable (`dataset_source=real|fixture`).
- **Pre-registered 4-stage elimination & pruning funnel:**
  1. *Stage 1 (Micro Falsification):* Eliminate cores failing synthetic associative recall (`MQAR-16 < 75%`) and drop zero-gain auxiliary objectives.
  2. *Stage 2 (Isolated Track Tournaments):* Select one winner per track (`Core*`, `Tokenizer*`, `Objective*`, `Decision*`, `Router*`, `Memory*`).
  3. *Stage 3 (Central Shared-vs-Split Interference Gate):* Test whether one shared `Core*` serves generation + calibrated decisions within `≤ 3.0%` BPB degradation and `≤ 2.0` Macro-F1 points loss vs. equal-budget split specialists (`D4`), adopting Split Dual-Pathway automatically if interference exceeds rejection bounds (`> 5%` BPB or `> 5` Macro-F1 loss).
  4. *Stage 4 ("Earn-Your-Place" Forward Assembly + Leave-One-Out Pruning):* Greedily attach surviving enhancements only when 5-seed paired bootstrap 95% CIs exclude zero within edge RAM/latency budgets, then prune any redundant component via Leave-One-Out ablation.
- **Canonical RecaMem Core Export:** Persist the winning architecture specification, ablation waterfall, and provenance-stamped ledger to `reports/recamem-core-selection.md`, `reports/evidence/recamem-core-tournament.json`, and `configs/recamem_selected_core.json`, plus a unified factory (`src/model/recamem_core.py`) implementing the repository's backend, decision, router, and plastic-adapter contracts for direct consumption as the core of `recamem`.

## Capabilities

### New Capabilities
- `model/core-candidates`: Pluggable `SequenceCore` interface, parameter-matching configurator (`±2%`), and implementations of all 7 candidate sequence-mixing backbones (`C0`–`C6`) for isolated comparison.
- `training/candidate-objectives`: Pluggable byte/BPE tokenization (`V=256` vs. `V=4096`), Track-2 training objectives (`O1`–`O3`), online RTRL vs. micro-batched chunked BPTT (`O4`), and non-colliding interleaved multi-task batching.
- `model/action-router`: Option-conditioned bilinear decision readout (`D3`), Split-Specialist control (`D4`), and the 4 five-way action router candidates (`R1`–`R4`) with deterministic risk-coverage and schema guards.
- `memory/candidate-stores`: Unified Track-5 memory benchmark interface wrapping persistent core state (`M0`), Engram hashed n-gram lookup (`M1`), surprise-gated residual episodic KV (`M2`), `KnowledgeStore` RRF (`M3`), `SparseDeltaAdapter` (`M4`), and online weight updates (`M5`).
- `evaluation/architecture-tournament`: Controlled benchmark suite (MQAR, Copy, BPB, Grammar/BLiMP, Length Extrapolation, Dynamic/Unseen-Option Calibration, Cost-Weighted Routing, Continual/Contradiction Retention, CPU/INT8 Efficiency) and automated 4-stage elimination + Leave-One-Out pruning engine.
- `recamem/core-selection`: Canonical export of the empirically winning architecture (`configs/recamem_selected_core.json`, `reports/recamem-core-selection.md`, `reports/evidence/recamem-core-tournament.json`, and `src/model/recamem_core.py`) ready to serve as the core of the `recamem` engine.

### Modified Capabilities
- `system1-decision`: Add support for variable per-request closed option sets ($K \in [2, 255]$), unseen option label phrasings, an explicit trained null/abstain class, held-out temperature calibration ($T_{\text{cal}}$), and selective risk-coverage evaluation (`AURC`, adaptive `ECE`).
- `evaluation/edge-performance`: Add cross-tokenizer held-out Bits-Per-Byte (`held_out_bpb`), prefill time-to-first-token (`ttft_ms`), dynamic INT8 decode throughput (`int8_tokens_per_second`), and paired Equal-Byte vs. Equal-Wall-Clock comparison tables.
- `evaluation/lifelong-benchmarks`: Extend continual retention benchmarking to compare all 6 memory/adaptation candidates (`M0`–`M5`) across multi-domain sequential teaching, non-monotonic contradiction updates, backward transfer, memory footprint per 10k facts, and adaptation latency.

## Impact

- **Code (`Experiment` branch, additive & non-breaking):** Adds modular candidate packages and tournament runners under `src/model/` and `scripts/` without breaking existing `DroidEngine`, `ByteRtuBackend`, `DecisionHead`, `DeltaPlasticAdapter`, or `post-merge-completion` gates.
- **Relationship to `recamem-plastic-memory-engine`:** Supplies the empirically validated built-in core architecture, decision/router pathway, and memory-channel winner that `recamem` (`recamem/backends.py`, `recamem/rtu.py`, `recamem/decision_head.py`, `recamem/engine.py`) adopts instead of relying on unverified byte-RTU or ad-hoc heuristics.
- **Hardware & Offline Portability:** Runs end-to-end on CPU-only hosts including constrained 2-vCPU / 3.8 GiB sandboxes via micro-batched gradient accumulation and labelled offline fixtures (`dataset_source=fixture`), while scaling cleanly to full 30M–100M token runs (`dataset_source=real`) when external corpora are cached.
- **Artifacts & Git Hygiene:** Model checkpoints and multi-run scratch directories remain git-ignored under `droids/` or temporary build directories; only deterministic configs, code, tests, human-readable synthesis reports, and compact JSON evidence ledgers are committed.
